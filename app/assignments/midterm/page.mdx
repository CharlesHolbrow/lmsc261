### Option 1: Compose with Python, then produce a track

Write a composition entirely in Python and save it as a MIDI file. Open that file in a DAW, or another workflow you already use, and produce a finished audio track.

**Starting Point:** [MIDI Chords](/assignments/midi-chords/). That assignment uses [MIDIUtil](/modules/midiutil/) to write a `.mid` file. The notes at the bottom of the page — rhythm, dynamics, sections — are the kinds of control a piece needs.

If you go this route, compose something _for_ the medium. Do something that takes unique advantage of Python and could not easily be made in a DAW. For inspiration, listen to [Conlon Nancarrow, Study for Player Piano No. 21 (Canon X)](https://www.youtube.com/watch?v=f2gVhBxwRqg). Nancarrow created music that could _only_ be played by a player piano.

Turn in the Python code, the `.mid` file, and a link to the finished audio.

### Option 2: Interactive instrument and visualizer

Build something you can play, with a picture that responds.

**Starting Point:** [Pygame MIDI](/modules/pygame-midi-hands-on/) or [Pygame Audio](/modules/pygame-audio-hands-on/).

Add your own changes until the result is a new instrument: a new way to play, or a new mapping from gesture to sound. Ideas include:

- Animate the circles so they move at different speeds and play sounds when they bounce off a surface or collide with each other.
- Use a completely different drawing approach from simple circles with an `x=pitch` `y=gain` mapping. Make it as beautiful and responsive as you can.
- Create a sequencer for writing interactive musical scores. For example, you could connect the circles with lines like a constellation, and then have a playhead that moves along the lines.

For inspiration, read parts 1 and 2 of Golan Levin's Thesis: [Painterly Interfaces for
Audiovisual Performance](https://acg.media.mit.edu/people/golan/thesis/thesis300.pdf)

### Option 3: Animation or game

Make an animation or a game.

**Starting Point:** The [Pygame tutorials](https://www.pygame.org/docs/#tutorials-reference-label) in the official documentation, and the [Pygame](/modules/pygame/), [Pygame: Hands-On](/modules/pygame-hands-on/), and [Pygame: Animation](/modules/pygame-animation/) modules from our class.

Look at [Zach Lieberman's sketches](https://www.instagram.com/zach.lieberman/). He posts a small visual program almost every day. Yours can be one sketch that you push until it holds together.

## Steps

1. Using [GitHub Desktop](https://desktop.github.com/), open the [homework repo](https://github.com/berklee-epd/lmsc261-homework)
2. **Pull/Sync** the latest (do this before the PR)
   - Current Branch → `main`
   - Fetch origin → Pull origin
3. Make a **branch** named `your-name-midterm`
   - Example: `ada-lovelace-midterm`
4. In **your** folder, create `midterm` with `uv`:

   ```bash
   uv init --no-package midterm
   cd midterm
   ```

   From inside `midterm`, add the libraries for your starting point.

   MIDI composition:

   ```bash
   uv add MIDIUtil
   ```

   Pygame:

   ```bash
   uv add pygame-ce numpy
   ```

   Add any other library you import the same way.

5. Open that `midterm` folder in [Visual Studio Code](https://code.visualstudio.com/)
   - File → Open Folder… → choose `midterm`
   - 🚨 Open `midterm`, not the parent homework folder. 🚨
6. Copy the README template below. Start every heading before October 22. Add to the same headings before October 29.
7. **Commit** in GitHub Desktop. Do not commit `.venv`.
8. **Push**
9. Click **Create Pull Request**
10. Title: `Your Name Midterm`
11. **🚨 Do not click Merge 🚨**

Keep committing to this branch. Do not open a second PR for the final.
