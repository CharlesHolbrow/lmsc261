# Python Conditionals

The pygame [examples](/assignments/pygame-audio/) use a `for` loop like this:

```python
...
for event in pygame.event.get():
    if event.type == pygame.QUIT:
        running = False
    elif event.type == pygame.MOUSEBUTTONDOWN:
        print(f"mouse down button={event.button} pos={event.pos}")
    elif event.type == pygame.MOUSEBUTTONUP:
        print(f"mouse up button={event.button} pos={event.pos}")
```

You need two ideas before this code will make sense: **comparison operators** and **conditional statements**.

[Python Basics](/modules/python/#conditionals) mentioned `if` in passing, but we skipped the details. The event loop is the reason to look at them now.

The editors below run in the browser. Press **Run**, or **⌘+Enter** / **Ctrl+Enter**.

## Comparison Operators

A comparison operator takes a value on the left and a value on the right. The result is `True` or `False`.

A **condition** is an expression whose value is `True` or `False`.

## Conditional Statements

`if` / `elif` / `else` are conditional statements, also called **branching**. They use those `True`/`False` answers to choose which lines run.

An `if` statement runs its **body**, the indented lines after the `:`, only when the condition is true.

<PyScriptEditor
  kind="mpy-editor"
  rows={10}
  outputRows={2}
  initialCode={`
bpm = 88

if bpm < 100:
    print("slow")

print("done!")
`}
/>

What will happen if you change `bpm` to `140` and run again? What about `100`?

## `else`

`else` is the other path, the lines that run when the condition is false.

<PyScriptEditor
  kind="mpy-editor"
  rows={10}
  outputRows={1}
  initialCode={`
event_type = "MOUSEBUTTONDOWN"

if event_type == "QUIT":
    print("close the window")
else:
    print("keep going")
`}
/>

## `elif`

`elif` means else if, so Python asks the next question only when the earlier answers were false.

<PyScriptEditor
  kind="mpy-editor"
  rows={16}
  outputRows={1}
  initialCode={`
bpm = 88

if bpm < 60:
    print("largo")
elif bpm < 80:
    print("adagio")
elif bpm < 108:
    print("andante")
elif bpm < 120:
    print("moderato")
elif bpm < 168:
    print("allegro")
else:
    print("presto")
`}
/>

88 is less than 108, and it is also less than 168. Separate `if` statements could print both `andante` and `allegro`. `elif` keeps the first match.

Change `bpm` to `50`, `130`, or `180` and run again. Only one name prints.

### `if` vs `elif`

A new `if` starts a new question, and it can run even if the previous `if` already ran. `elif` belongs to the same decision, so it runs only when nothing above it matched.

<PyScriptEditor
  kind="mpy-editor"
  rows={20}
  outputRows={5}
  initialCode={`
event_type = "MOUSEBUTTONDOWN"

print("two separate ifs:")
if event_type == "QUIT":
    print("close the window")
if event_type == "MOUSEBUTTONDOWN":
    print("start a note")
if event_type != "QUIT":
    print("keep going")

print("if / elif:")
if event_type == "QUIT":
    print("close the window")
elif event_type == "MOUSEBUTTONDOWN":
    print("start a note")
elif event_type != "QUIT":
    print("keep going")
`}
/>

The first block prints `start a note` and `keep going`. The second prints only `start a note`.

Change `event_type` to `"QUIT"` or `"SOUND_DONE"` and run again.

That is the difference in the pygame loop too. `elif event.type == audio.SOUND_DONE` means we only check whether the sound finished if we have not already handled this event as quit, mouse down, or mouse up.

## Nested `if`

You can put a second `if` in the body of another. In the starter, mouse-down handling asks a follow-up question about whether it was the left button. `1` is the left mouse button in pygame.

<PyScriptEditor
  kind="mpy-editor"
  rows={14}
  outputRows={2}
  initialCode={`
event_type = "MOUSEBUTTONDOWN"
button = 1

if event_type == "MOUSEBUTTONDOWN":
    print("mouse down")
    if button == 1:
        print("left click: play a note")
    else:
        print("some other button")
`}
/>

Try `button = 3` for a right click. The inner `if` never runs unless the outer one matched.

The starter then nests `if channel:`, which stores the click only when `play` actually gave us a mixer channel.

## `and`, `or`, `not`

These operators let you ask more than one question in a single `if`.

<PyScriptEditor
  kind="mpy-editor"
  rows={12}
  outputRows={3}
  initialCode={`
event_type = "MOUSEBUTTONDOWN"
button = 1
x = 200
WIDTH = 680

if event_type == "MOUSEBUTTONDOWN" and button == 1:
    print("left click")

if x >= 0 and x < WIDTH:
    print("inside the window")

if not event_type == "QUIT":
    print("not quitting")
`}
/>

`and` is true only when both sides are true, `or` is true when at least one side is true, and `not` flips true and false.

## Values that count as true

Not every `if` uses `==`. `if channel:` asks whether `channel` counts as true. `None`, `0`, `""`, and `[]` count as false, and almost everything else counts as true.

<PyScriptEditor
  kind="mpy-editor"
  rows={12}
  outputRows={2}
  initialCode={`
channel = None

if channel:
    print("got a mixer channel")
else:
    print("no free channel")

channel = 3

if channel:
    print("got a mixer channel")
`}
/>

That is why the starter writes `if channel:` after `sampler.play(...)`. If every mixer voice is busy, `play` returns `None`, and we skip storing a click position.
