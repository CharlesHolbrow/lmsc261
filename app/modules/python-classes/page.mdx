# Python Classes

You have already used classes. In [MIDIUtil](/modules/midiutil/) you wrote:

```python
midi = MIDIFile(1)
midi.addNote(0, 0, pitch=60, time=0, duration=1, volume=100)
```

In [Pygame Audio](/assignments/pygame-audio/) you wrote:

```python
sampler = audio.Sampler("c4.wav")
sampler.play(60)
```

A **class** connects **data** with the **functions** that operate on that data. In the `MIDIFile` example:

- **data**: A sequence of MIDI events
- **functions**:  [`addNote`](https://midiutil.readthedocs.io/en/1.2.1/class.html#midiutil.MidiFile.MIDIFile.addNote), [`addControllerEvent`](https://midiutil.readthedocs.io/en/1.2.1/class.html#midiutil.MidiFile.MIDIFile.addControllerEvent), etc

## Add attributes

This is the simplest possible class is just \`pass\` (do nothing)


<PyScriptEditor
  kind="mpy-editor"
  rows={10}
  outputRows={1}
  initialCode={`
class Note:
    pass

# Create an instance of the class
c4 = Note()

# Add data with a dot. 
c4.pitch = 60
print(c4.pitch)
`}
/>

`Note()` makes one object, also called an **instance**.

`pitch` is an "attribute". Sometimes people also call it a "property"

Change `60` to `64` and run again. `c4.pitch` is data that lives on this one object.

## Two objects, two sets of data

Each instance has its own attributes.

<PyScriptEditor
  kind="mpy-editor"
  rows={14}
  outputRows={2}
  initialCode={`
class Note:
    pass

c4 = Note()
c4.pitch = 60

a4 = Note()
a4.pitch = 69

print(c4.pitch)
print(a4.pitch)
`}
/>

`c4` and `a4` are both instances of `Note`. Changing one does not change the other.

Change `a4.pitch` to `72` and run again. `c4.pitch` stays `60`.

## Methods

A function inside a class is a **method**. The first parameter is `self`. When you call it with a dot, Python fills in `self` with the object on the left.

<PyScriptEditor
  kind="mpy-editor"
  rows={14}
  outputRows={1}
  initialCode={`
class Note:
    def describe(self):
        print(f"pitch {self.pitch}")

c4 = Note()
c4.pitch = 60
c4.describe()
`}
/>

`c4.describe()` runs `describe` with `self` set to `c4`. You do not write `c4` inside the parentheses.

Change `c4.pitch` and run again. `self.pitch` is whatever pitch lives on that object.

## `__init__`

Setting `c4.pitch = 60` after you create the object works, but it is easy to forget. `__init__` runs when you make an instance. That is the place to set the attributes.

The name is "init" with two underscores on each side. People say "dunder init" (double underscore).

<PyScriptEditor
  kind="mpy-editor"
  rows={16}
  outputRows={2}
  initialCode={`
class Note:
    def __init__(self, pitch):
        self.pitch = pitch

    def describe(self):
        print(f"pitch {self.pitch}")

c4 = Note(60)
a4 = Note(69)
c4.describe()
a4.describe()
`}
/>

`Note(60)` calls `__init__`. `self` is the new object. `pitch` is `60`. The body stores that on the object: `self.pitch = pitch`.

That is why `MIDIFile(1)` and `Sampler("c4.wav")` take arguments. Those arguments go to `__init__`.

Change `60` to `72` and run again.

## A method that changes the object's data

Methods can also **change** the attributes on `self`. That is the payoff of bundling: the function already knows which object's data to update.

<PyScriptEditor
  kind="mpy-editor"
  rows={18}
  outputRows={2}
  initialCode={`
class Note:
    def __init__(self, pitch):
        self.pitch = pitch

    def transpose(self, semitones):
        self.pitch = self.pitch + semitones

c4 = Note(60)
a4 = Note(69)
c4.transpose(2)
print(c4.pitch)
print(a4.pitch)
`}
/>

`c4` moved up two semitones, from 60 to 62. `a4` stayed at 69. `transpose` changed only the object before the dot.

Change the `2` to `-12` (down an octave) and run again.

## Look back

```python
midi = MIDIFile(1)
midi.addNote(0, 0, pitch=60, time=0, duration=1, volume=100)
```

`MIDIFile` is a class. `MIDIFile(1)` runs `__init__` and gives you an instance named `midi`. `midi.addNote(...)` is a method. The notes are data on `midi`. `addNote` is a function that operates on that data.

```python
sampler = audio.Sampler("c4.wav")
sampler.play(60)
```

Same shape. The wav lives on `sampler`. `play` uses it.
